# Evidence Room — AP Agent OS Professional

## 00 — Professional Operating System

**Product:** Evidence Room AP Agent OS — Professional  
**Brand idea:** Proof before permission.  
**Line:** Agents earn responsibility. Evidence decides.  
**Audience:** Head of AP, Controller, Transformation lead, Control owner, Finance Systems  
**ERP stance:** Agnostic. Map field names locally. Do not copy another company’s workflow.  
**Examples:** ACME Manufacturing — **ILLUSTRATIVE** only.  
**Version:** 1.0  
**Classification:** Navigation and START HERE path. This file does not replace charters, controls, or test packs.

---

### Position

Professional is the operating system for a **governed** accounts payable agent programme: sixteen named agents, a human accountability model, a control and exception language, a measurement dictionary, and a test path that earns each increment of responsibility.

It is not a prompt pack. It is not a guarantee of savings, ROI, fraud detection, statutory compliance, or autonomous payment.

If you need a facilitated enterprise pack (workshop, training, steering, change), use **Team Edition** (`../04_AP_AGENT_OS_TEAM/`). If you need a paid, time-boxed blueprint service, use **Custom Blueprint** (`../05_CUSTOM_BLUEPRINT/`).

## START HERE — path 01 to 12

Do these in order for the **first increment**. Skipping a step to “get to the agent” produces an unauthorised next step.

| Step | What you should do | Primary files | Exit evidence |

| **05** | Charter **one** agent at **L0**. Deterministic vs model split. Forbidden tools listed. | `Agent_Library/19_AGENT_CHARTER_STANDARD.md`; matching `AGENT_0X`; `Templates/AGENT_CHARTER.md`; `Governance/01_AUTONOMY_POLICY.md` | Signed charter |
| **06** | Complete control matrix rows, risk assessment, SoD/identity intent. | `Controls/00_CONTROL_FRAMEWORK.md`; `01_CONTROL_MATRIX.md`; `02_RISK_REGISTER.md`; `Templates/RISK_ASSESSMENT.md` | RA + matrix rows |
| **07** | Freeze baseline KPIs and the cost model (even if AI cost is zero). | `KPI_and_Measurement/00_KPI_FRAMEWORK.md`; `01_KPI_DICTIONARY.md`; `Business_Case/01_COST_PER_INVOICE.md`; `00_BUSINESS_CASE_MODEL.md` if funding | Baseline ID; CPI version |
| **08** | Historical test on a labelled pack you own. | `Testing/00_TESTING_STANDARD.md`; `01_HISTORICAL_TEST_SCRIPTS.md` | Test Go / Hold / Redesign / Stop |
| **09** | UAT — can named people operate the path? | `Testing/02_UAT_TEMPLATES.md`; `Templates/UAT.md` | UAT Go |
| **10** | Shadow — live compare, **no action verbs**. | `Testing/03_SHADOW_MODE.md` | Shadow recommendation |

**Typical first agents:** 01 Intake, 10 Duplicate, 16 Orchestrator at L0 — then 02/03. **Leave 12 Payment at recommend/prepare.** Payment release, bank-change, policy exception, and legal dispute stay human from day one.

Time: a **well-bounded** first agent may fit an **ILLUSTRATIVE** 4–6 week observe-to-shadow path (`Business_Case/03_IMPLEMENTATION_ROADMAP.md` §4) with explicit caveats. A multi-entity stack will not.

## Operating rule (every artefact)

Each working section answers:

1. **What** should I do?  
2. **How**?  
3. **Who** owns it?  
4. What can go **wrong**?  
5. How do I **control** it?  
6. How do I **measure** it?  
7. What **evidence** proves it?

---

## What stays human

Payment release · Vendor bank-change approval · Policy exceptions · Legal disputes.

Confidence may narrow action. It may not widen a control. Agents are never Accountable.

---

## What this OS is not

- A promise that cycle time or cost will fall.  
- A compliance certificate or fraud-detection product.  
- A licence to bypass ERP controls, DOA, or SoD.  
- Permission to process payments without the buyer’s authorisation path.

Proof before permission. Agents earn responsibility. Evidence decides.
