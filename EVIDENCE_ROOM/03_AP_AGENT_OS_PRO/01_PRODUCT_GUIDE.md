# AP Agent OS Pro — Product Guide

**Evidence Room** · Pro  
**Positioning:** The governed agent operating system for Accounts Payable — templates, controls discipline, testing, and KPIs.  
**Principle:** Agents that earn responsibility.

## 1. Who Pro is for

| Primary | Secondary |
|---|---|
| AP Manager / Director designing first serious agents | Controller / Finance Transformation |
| P2P lead with existing AP stack | Shared services process owners (with Team) |

**Anti-buyer:** Teams seeking magic OCR + pay with zero governance.

## 2. Job to be done

When we introduce AI into AP, help us decide what agents may do, under what evidence, with whom accountable, how we measure against **our** baselines, and how responsibility expands only after proof — without ripping out our stack.

## 4. Earn-up model

| Stage | Agent may | Human must |
|---|---|---|
| Observe | Summarize, classify, flag | Decide all actions |
| Recommend | Propose coding, match, route | Approve / reject |
| Draft | Prepare emails, packs, notes | Send / post |
| Execute (narrow) | Allow-listed micro-actions | Own outcome + sampling |
| Expand | Broader scope after gates | Explicit promotion |

Default left. Demote freely.

## 5. Canonical agents (reference)

**A01–A10:** Intake, Validation, Matching, Exception Triage, Goods Receipt, PO Quality, Approval, Supplier Resolution, Internal Follow-Up, Duplicate/Anomaly (*signals ≠ fraud guarantee*).  
**A11–A16:** Statements, Payment Proposal Review, AP Close, Reporting, Root Cause, Orchestrator — deeper Pro library territory; Payment Proposal remains recommend-oriented; payment release stays human.

## 11. Recommended first pilot pattern

1. Domestic PO class under a money threshold  
2. Agents: Intake (Observe/Recommend) + Validation + Exception Triage  
3. Matching Recommend only after validation quality holds  
4. No payment agent authority  
5. 30-day shadow → pilot decision
