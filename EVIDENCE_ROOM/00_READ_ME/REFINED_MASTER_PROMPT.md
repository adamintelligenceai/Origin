## 7. NON-NEGOTIABLE PRODUCT PRINCIPLES

1. **Responsibility is earned.** Default is Observe. Autonomy is never the default.
2. **Humans own outcomes.** Agents have owners. Payment authorisation stays human.
3. **Evidence before autonomy.** No Level 3+ without a performance history.
4. **Deterministic first.** Matching tolerances, duplicate keys and DoA limits are rules. Language models recommend, classify, draft and explain — they do not invent postings or bank details.
5. **Least privilege.** Agents get the minimum data and action rights for the current level.
6. **Segregation of duties.** No agent both prepares and authorises a payment.
7. **Fail closed.** Ambiguous, low-confidence or injection-suspicious output stops and escalates.
8. **ERP-agnostic.** The OS sits above systems.
9. **Monday-ready.** Bought Friday, workshopable Monday.
10. **IP-clean.** Independently authored. No employer, client or copyrighted consulting material.
11. **No invented numbers.** Every market or benchmark claim sits in the research ledger or is labelled illustrative.
12. **One question per page.** What should I do? How? Who owns it? What can go wrong? How do I control it? How do I measure it? What evidence proves it?

## 8. THE 5-LEVEL RESPONSIBILITY MODEL (CANONICAL)

| Level | Name | Agent may | Agent may not | Promotion evidence |
|---|---|---|---|---|
| 0 | Observe | Read, label, log | Recommend a decision as authoritative | Instrumented data access + audit log |
| 1 | Recommend | Produce a recommendation with rationale and confidence | Write back, message externally, change records | Accuracy vs labelled set; false-positive/negative within gate |
| 2 | Prepare | Draft comms, coding, match packets, follow-ups | Send, post, pay, change master data | Dual-review sample; rework rate below gate |
| 3 | Execute within guardrails | Perform pre-approved low-risk actions inside hard limits | Anything outside the written guardrail; any payment | Shadow + pilot metrics; zero critical control breaches |
| 4 | Managed autonomy | Operate in a bounded population with exception-based review | Expand its own scope; change its own controls | Sustained KPI window; periodic recertification |

Promotion is a management decision with a named human owner, not an automatic model score.

Every agent file uses this exact schema:

2. Job description  
3. In-scope / explicit exclusions

5. Tools and systems (read vs write)  
6. Business rules and deterministic checks  
7. Decision / exception taxonomy mapping  
8. Outputs and output standard  
9. Human owner and RACI  
10. Approval requirements by responsibility level  
11. Escalation criteria  
12. Control requirements and audit evidence  
13. KPIs and scorecard  
14. Failure handling and fallback  
15. Cost monitoring  
16. Worked example (realistic, fictional company)  
17. Instruction block (system + task — not a toy prompt)  
18. Testing cases (pass / fail / edge)

**Agents (fixed set):**

| ID | Agent | Primary job |
|---|---|---|
| A01 | Invoice Intake | Completeness and extraction fitness of inbound invoices |
| A02 | Invoice Validation | Supplier, number, date, PO, entity, currency, amount, tax, lines, duplicates, required fields |
| A03 | Matching | PO / price / qty / receipt / tolerance / multi-line |
| A04 | Exception Triage | Classify into the taxonomy and recommend next action |
| A05 | Goods Receipt | Missing / partial GR, likely owner, follow-up pack |
| A06 | PO Quality | Price, qty, expiry, coding, vendor, blanket-PO misuse |
| A07 | Approval | Stalled items, absence, delegation, hierarchy, payment-deadline risk |
| A08 | Supplier Resolution | Draft supplier comms; send only if configured and approved |
| A09 | Internal Follow-Up | GR, PO, approval, coding, requester, business-owner actions |
| A10 | Duplicate & Anomaly | Exact / near dupes, amount patterns, invoice-number variation, unusual payment traits — *indicators only* |
| A11 | Vendor Statement Reconciliation | Statement vs AP; missing items; timing differences |
| A12 | Payment Proposal Review | Pre-payment analytical review; **never authorises payment** |
| A13 | AP Close | Unresolved / unprocessed / blocked, aged receipts, accrual candidates, cut-off, completeness |
| A14 | AP Reporting | Daily / weekly / monthly operating packs |

## 10. METHODOLOGY (10 STEPS — TEMPLATES REQUIRED)

Observe → Transcribe → Extract → Structure → Agentise → Test → Shadow → Controlled Pilot → Measure → Expand responsibility.

Each step has: purpose, roles, inputs, outputs, timebox, quality check, template, and a fictional worked example.

**Agentise rule:** Prefer deterministic automation for match math, duplicate keys, DoA limits, and status updates. Use agents for classification, explanation, drafting, prioritisation, root-cause narrative, and incomplete-information handling.

## 13. KPI AND ECONOMICS RULES

Separate four families. No vanity metrics.

| Family | Examples | Rule |
|---|---|---|
| Activity | invoices handled, exceptions touched | Never report alone |
| Operational | STP, cycle time, exception resolution, ageing | Primary management view |
| Financial | cost/invoice, hours released, discount capture, late-payment cost | Ranges + sensitivity, not fake precision |
| Risk / control | control breaches, audit exceptions, override rate, injection incidents | Hard gates for promotion |

Every KPI has: name, question it answers, formula, data source, owner, cadence, target-setting note, gaming risk.

Business case model inputs: invoice volume, AP FTE, fully loaded cost, manual-touch %, exception rate, minutes per exception, duplicate rate, late-payment cost, early-pay discount opportunity, processing cost, AI/tool cost, implementation cost, efficiency range.

Outputs: baseline cost, capacity released, processing- and exception-cost change, estimated savings, payback, ROI, Conservative / Base / Upside.

Label illustrative models as illustrative. Cite independent benchmarks in the ledger, not as the customer’s actuals.

## 18. EVIDENCE PROTOCOL

Before any customer-facing number:

1. Find a reputable source.  
2. Capture claim, exact figure, date, URL, context, independence (independent / vendor-sponsored / vendor-claim / market-estimator / illustrative).  
3. Prefer Ardent Partners, IOFM, Hackett, McKinsey, Deloitte, PwC, EY, KPMG, Gartner, Forrester, NIST, statutory guidance.  
4. Market-size houses (Mordor, FMI, Research and Markets) may be recorded but must be labelled as estimator firms — not as Gartner.  
5. Vendor-commissioned Forrester snapshots are vendor-originated.  
6. If two reputable sources disagree, show the range and the vintage. Do not average them into a fake “truth.”  
7. Customer PDFs use sparse, elegant citations. The ledger holds the full apparatus.

No statistic may appear in a sellable file unless it is in `09_RESEARCH/EVIDENCE_LEDGER.csv`.
