# Evidence Room — AP Agent OS
## Refined Master Execution Spec (v1.0)

This document is the tightened operating brief used to build the commercial product. It converts the original master prompt into locked decisions, acceptance tests, evidence rules, and an artifact contract.

---

### 0. What this product is

**Evidence Room** is a digital-product company that sells implementation-ready operating systems for Finance agents.

**AP Agent OS** is the first vertical. It is a toolkit a Finance leader can buy on Friday and use on Monday to:

1. diagnose AP agent readiness
2. map the current AP process
3. specify agents as governed roles
4. classify and route exceptions
5. set controls, KPIs and autonomy gates
6. test, shadow, pilot and expand responsibility
7. build a conservative business case
8. run a workshop or steering committee with the same language

It is **not** software, an ERP, a payment rail, a prompt pack, an ebook, or a promise of autonomous AP.

**Category line:** Operating system for Accounts Payable agents.  
**Anti-category:** Not another AP automation platform. Not another AI prompt bundle.

### 3. Product principle (content filter)

Every page must answer at least one:

1. What should I do?
2. How should I do it?
3. Who owns it?
4. What can go wrong?
5. How do I control it?
6. How do I measure it?
7. What evidence proves it works?

If none, delete.

---

### 4. Commercial tests (must pass)

1. Would a Finance Director responsible for ~15,000 invoices/month pay **$199 of their own money** because this saves days of research and gives a credible implementation framework?
2. Could a Transformation lead run a **credible workshop tomorrow** from the Team Edition?
3. Does the buyer immediately understand this is an **OS for Finance agents**, not a prompt pack?

If any answer is not clearly yes, revise before shipping.

Quality floor: 9/10 on content, practicality, specificity, design, credibility, differentiation, coherence, usability, commercial value.

### 5. Evidence protocol

For any claim about market size, cost, cycle time, exception rate, STP, AI adoption, or similar:

- Use a named source, date, and URL
- Classify as Independent / Vendor / Illustrative / Evidence Room framework
- Prefer Ardent Partners, NIST, COSO, ISO, Big Four, McKinsey, Gartner/Forrester when available
- If a figure cannot be verified, do not use it
- Customer-facing documents cite lightly; the research ledger holds the full trail

Primary independent benchmarks used in this build (June 2025, Ardent Partners *State of ePayables 2025*, n=204):

- Average all-in cost per invoice: **$9.84**
- Average cycle time: **8.2 days**
- Average exception rate: **18.4%**
- Straight-through processing: **35.4%**
- Best-in-Class cost: **$2.65** vs All Others **$12.42**
- Best-in-Class cycle: **2.9 days** vs All Others **13.5**
- AI in use in AP: **44%**; +34% planning within 12 months; **22%** no current plans
- Top AP challenges: approvals too long **49%**; high exceptions **48%**
