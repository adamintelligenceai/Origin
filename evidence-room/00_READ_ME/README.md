## What you have

Accounts Payable already has a stack: capture, match, workflow, ERP, bank. What it rarely has is an operating system for the agents now being dropped into that stack.

This suite specifies that layer: sixteen named roles, an evidence standard, a permission ladder (L0–L4), and a written list of decisions that stay human. Payment authorisation remains human at every autonomy level.

## Friday-to-Monday path

A Controller, AP Manager, or Finance Transformation lead can do useful work in one weekend without commissioning a bot.

### Friday afternoon (60–90 minutes)

1. Read this file and `QUICK_START.md`.
2. Complete the diagnostic in `01_FREE_AP_AI_READINESS/DIAGNOSTIC_GUIDE.md` with last quarter’s facts, not hopes.
3. Score 0–4 on each question. Do not average away a 0 on payment control.
4. Place the organisation on the L1–L5 maturity model. Write the band in one sentence.

### Saturday (2–3 hours)

5. Open `02_AP_AGENT_STARTER/STARTER_GUIDE.md` and the human-vs-agent one-pager.
6. Take the last ten exceptions and the last payment run. Classify each decision. Record where a vendor demo would have auto-released cash.
7. Charter Wave 1 only: Intake, Validation, Matching, Exception Triage, Duplicate & Anomaly, Orchestrator — at L0 or L1. Blank charters live in Starter; full specs live in Professional (`03_AP_AGENT_OS_PRO/Agent_Library/`).
8. Write the payment sentence on the wall: **Agent 12 annotates. Humans release.**

### Sunday (90 minutes)

9. Name one human owner and one backup for each Wave 1 agent. If you cannot name them, do not commission the agent.
10. Draft the first-week sampling plan: coverage, coded fail reasons, match worksheets, flag outcomes.
11. If you hold Professional or Team, skim `03_AP_AGENT_OS_PRO/Business_Case/NINETY_DAY_PLAN.md` and put Phase 0 on a calendar. Do not build a savings slide.

### Monday morning (45 minutes)

12. Circulate a one-page note: band, Wave 1 names, owners, payment hold, and the request for a 30-day control review with Internal Audit as observer.
13. Stand agents at L0 (shadow) if — and only if — owners, object types, and the evidence standard are written.
14. Refuse any proposal to “just turn on auto-post” or “just release under $5k.”

That is a complete first cycle. Promotion is a later, evidence-gated decision. See `03_AP_AGENT_OS_PRO/Agent_Library/AUTONOMY_PROGRESSION.md`.

## What “done” means in the first 30 days

Not a savings number. Not a fraud-catch count. Not a compliance certificate.

- Every inbound invoice in the pilot path has a work object.
- Validation fail reasons are coded.
- A defined sample of match worksheets can be reopened.
- Duplicate & Anomaly flags have a recorded human outcome (clear / confirm / escalate / defer).
- The autonomy register shows every live agent at L0 or L1.
- No payment left the organisation without the human release path your policy already requires.

If first-time match or cycle time later moves, treat that as an observed outcome. It is not why this toolkit exists.

## Hard rules (read once, keep)

1. **Payment authorisation stays human.** There is no L3 or L4 path to release, transmit, or approve a payment run.
2. **A flag is a hypothesis, not a verdict.** Do not write “fraud” on Agent 10 output.
3. **ERP remains the system of record for accounting.** The Orchestrator is the system of record for work-object state.
4. **The method is ERP-agnostic.** Map roles onto SAP, Oracle, Dynamics, NetSuite, Workday, or the stack you have. Do not invent a connector.
5. **Northline is fiction.** Do not present its dollars or rates to a board as comparables.
6. **Do not invent statistics.** Cite only sources named in the file you are using. If a number is illustrative, say so in the same sentence.
7. **If it is not in the charter, the agent does not do it.**
8. **Staffing gaps are queue problems, not autonomy arguments.**
