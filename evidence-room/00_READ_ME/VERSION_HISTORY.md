## 1.0.0 — 20 September 2026 — First public edition

**Status:** Working edition.  
**Scope:** Complete authoring of the navigation, diagnostic, Starter, Professional (library, process, governance, KPI, testing, business case, templates), Team, Custom Blueprint, commercial, store, and legal-draft packs.

### What this edition contains

- Sixteen named agent specifications and the stack overview.
- Autonomy progression L0–L4 with written gates and payment hard ceiling.
- Human-vs-agent decision framework and exception taxonomy.
- 36-question readiness diagnostic across six dimensions; maturity model L1–L5.
- Starter operating model and ten-agent blueprints.
- Business-case model with Conservative / Base / Upside cases, no false precision, and cited research only.
- Team workshop, trackers, and enterprise governance overlay.
- Custom Blueprint fulfilment at $1,500–$3,000.
- Brand system: **Proof before permission.**

### Design decisions locked in this edition

| Decision | Rationale |
|---|---|
| Payment authorisation never an agent right | Cash movement is class A; no promotion path |
| Default commissioning at L0/L1 | Permission is withheld until evidence exists |
| ERP-agnostic architecture | The product is a layer design, not a connector |
| Northline Industrials is fictional | Concrete examples without fake case studies |
| No invented statistics | Only named sources, labelled when vendor-originated |
| Lockup always includes AP AGENT OS | Distinguishes from Evidence Room LLC (forensic animation) |
| Individual vs Team vs Blueprint | Licence matches how many pens sit on the files |

### Known limitations (not defects)

- Legal files are drafts for counsel. They are not in-force instruments until confirmed.
- No ERP certification or hosted runtime ships in 1.0.0.
- Diagnostic bands are readings, not certifications.
- Business-case outputs are calculator results from the buyer’s inputs. They are not Evidence Room promises.
- Trademark and domain clearance remain professional items. See `10_LEGAL_AND_LICENSING/TRADEMARK_AND_DOMAIN_NOTES.md`.

### Sources cited in this edition (business-case pack)

Cited only where a file needs an external figure. Do not reuse these numbers as “typical customer results.”

- Ardent Partners, *State of ePayables 2024*, as cited by Tipalti: cost per invoice $2.78 (best-in-class electronic) vs $12.88 (laggards); cycle time 3.1 vs 17.4 days. **Vendor-originated citation of independent research.**
- Ardent Partners, *AP Metrics that Matter 2025*, as cited by Tipalti: exception rate 22% → 9% in that research’s comparison. **Vendor-originated citation of independent research.**
- McKinsey, November 2025 finance AI research: 44% of 102 CFOs reported using gen AI for five or more use cases (from 7%); 65% increasing gen AI investment.
- McKinsey, *State of AI 2025* (survey June–July 2025, n=1,993): 88% regular AI use; roughly two-thirds not scaling; 62% experimenting with agents; 23% scaling an agent somewhere in the enterprise; 39% report any EBIT impact. Workflow redesign is identified as a high-performer differentiator.

If a later edition adds a source, it must name the publication, date, sample, and whether the path is direct or vendor-originated. If it cannot, the number does not ship.

## Versioning rules

| Segment | When it changes |
|---|---|
| Major (x.0.0) | Architecture change (agent count, autonomy model, payment rule) or a claim-policy change |
| Minor (1.x.0) | New module, new template family, or a material rewrite of a gate |
| Patch (1.0.x) | Typo, cross-link, clarification that does not change a rule |

Withdrawn claims cannot be patched back in. If a sentence is removed because it implied savings, fraud detection, compliance, accounting accuracy, autonomous payments, or ROI, the next edition must not restore it.

Northline figures may be edited only when labelled illustrative. They must never be recast as observed customer results.

---

## How buyers should treat updates

1. Keep the edition number on working charters.
2. Do not mix gate tables from two editions on one live agent.
3. If an update tightens a hold (for example, a new human-only class), adopt it before the next promotion case.
4. If an update loosens a hold, do not adopt it without Controller and Controls sign-off.
