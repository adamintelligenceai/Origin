**Ledger refs:** GAP-01 … GAP-06; Ardent context A2025-*, A2024-* for problem climate only.

---

## 1. Framing

Incumbent vendors below primarily sell **capture, workflow, payments, and/or ERP-adjacent finance automation**. Prompt-pack marketplaces sell **content snippets**. Neither category fully productises an **ERP-agnostic agent operating system** with responsibility progression, agent governance toolkit, and exception taxonomy + KPI OS for workforce design.

Evidence Room’s wedge: design and govern the **agent layer across** the stack the buyer already owns — not displace it.

## 3. Over-served vs under-served

### Over-served (do not compete head-on)

- Invoice capture accuracy races  
- Native payment rails and supplier networks  
- Deep single-ERP transaction posting  
- Generic “AI assistant in the AP inbox” feature marketing  

### Under-served (Evidence Room focus)

- ERP-agnostic **agent operating model** (GAP-02)  
- **Responsibility progression** — promotion/demotion of agent authority (GAP-03)  
- **Agent governance toolkit** — RACI, change control, audit evidence (GAP-04)  
- **Exception taxonomy + KPI OS** for designing an agent workforce (GAP-05)  
- Cross-stack design that assumes Tipalti/Coupa/Basware/etc. remain in place (GAP-06)

### Partially served (watch, don’t copy)

- HighRadius / UiPath-style “autonomous” messaging without finance-grade earned-responsibility OS  
- Microsoft Copilot-for-finance narratives without AP exception taxonomy productisation  
- Vendor AI features that optimise *inside* one platform’s workflow only

## 4. Evidence Room wedge

| Buyer question | Platform answer | Evidence Room answer |
|---|---|---|
| Can we capture and pay invoices? | Yes — buy/configure AP suite | Out of scope; keep your suite |
| Which agent may touch which invoices? | Often implicit in workflow rules | Explicit role cards, thresholds, stop conditions |
| When does the agent get more authority? | Rarely productised | Responsibility progression rules |
| How do we measure agent labour quality? | Platform KPIs for process, not agent workforce design | KPI OS + exception taxonomy |
| How does Audit review AI work? | Logs vary | Governance + evidence packs |
| Will this replace Coupa/Tipalti/…? | N/A | **No** — designs the agent layer across them |

## 5. Positioning rules (sales & web)

1. Name platforms as **complements**, never as failed legacy.  
2. Prefer “across your AP stack” over “better than [Vendor].”  
3. When citing industry pain, use Ardent ledger IDs — e.g. peer exception **18.4%** and STP **35.4%** (A2025-03, A2025-04) — not competitor disparagement.  
4. Prompt marketplaces: respect as content sources; state clearly they are **not** an operating system.  
5. UiPath: acknowledge automation strength; differentiate on **AP agent workforce governance and KPI OS**, not on RPA breadth.
