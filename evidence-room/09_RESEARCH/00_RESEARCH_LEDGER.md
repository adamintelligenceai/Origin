# Research Ledger — Evidence Room / AP Agent OS

**Purpose:** Traceable claims only. Every commercial, product, or market statement used in sales, website, or decks must map to a Claim ID here — or be marked as framework/opinion (see final section).

**Independence labels**

| Label | Meaning |
|---|---|
| Independent | Primary source from the party that sets the fact (e.g. MoR fee schedule, registrar, standards body) |
| Vendor | Claim originates from a product vendor’s own marketing/docs |
| Secondary citation | Third party repeating another analyst/vendor figure — use only with attribution; do not treat as primary evidence |
| Theme | Industry pattern observed across multiple sources; no numeric claim |
| Internal | Evidence Room product definition / positioning (not market evidence) |

**Update rule:** Prefer primary URLs. If a figure is only available via a vendor blog quoting Ardent Partners (or similar), keep the row, mark **Secondary citation**, and never present it as Evidence Room primary research.

## How to cite these claims externally

1. **Customer-facing ROI math:** Only use C-AP-101–105 with explicit “according to [secondary source] citing Ardent Partners…” language — or obtain the primary Ardent eBook and upgrade Independence.
2. **Vendor AI capabilities:** Cite as competitor claims (C-HR-*, C-TIP-*, C-STA-*). Never imply Evidence Room measured those outcomes.
3. **Lemon Squeezy margins:** Use C-LS-001/002 as Independent. Recheck pricing page before every price change.
4. **Themes (C-MKT-*):** Allowed in narrative (“teams struggle with…”). Forbidden as statistics.

## Evidence Room frameworks (not evidence)

These are **product/design constructs**. They organize work; they are **not** market proof, benchmarks, or guarantees.

| Framework ID | Name | What it is | Must not be sold as |
|---|---|---|---|
| F-ER-01 | Evidence Room | Operating metaphor: every agent action needs a receipt (who, what, why, control, KPI) | Proof that buyers already demand this category name |
| F-ER-02 | AP Agent OS | Product architecture: governance + responsibility + KPI + control for AP agents | A certified standard or industry-regulated OS |
| F-ER-03 | Responsibility Map | RACI-style ownership for agent roles (propose / approve / post / pay) | Legal assignment of liability |
| F-ER-04 | Control Catalog | Library of SoD, approval thresholds, dual-control, audit trails | Guaranteed fraud prevention or compliance certification |
| F-ER-05 | KPI Measurement Pack | Baseline → target → instrument → review cadence for AP agent outcomes | Guaranteed savings, STP%, or cycle-time reduction |
| F-ER-06 | Agent Readiness Score | Diagnostic for process/data/control maturity before agent rollout | Predictive model of implementation success |
| F-ER-07 | Exception Taxonomy | Classification of invoice exceptions for routing and learning loops | Universal industry taxonomy |
| F-ER-08 | Evidence Pack (sales) | Bundle of worksheets that force claims to map to Claim IDs | Third-party audited research |

**Rule:** If a sentence cannot point to a Claim ID **or** an Internal framework ID, do not publish it.
