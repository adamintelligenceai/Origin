# Implementation checklist — Starter

**Product:** Evidence Room — AP Agent OS · Starter  
**Use:** Tick in order. A skipped payment-hold line is not a time-saver.  
**Owner of the list:** the named practitioner on the Individual licence.

Items marked **GATE** must be true before the next section starts. Items marked **STOP** pause the programme if they become true later.

Northline examples are fictional.

---

## 0. Licence and hygiene

- [ ] I am the named Individual licensee (or I have Team/Professional rights).
- [ ] I will not upload production invoices, bank details, or employee files to Evidence Room.
- [ ] I have told colleagues this is a method pack, not software that “goes live.”
- [ ] I have read the payment sentence: Agent 12 annotates; humans release.

---

## 1. Diagnose

- [ ] 36-question diagnostic completed with a challenger (`01_FREE_AP_AI_READINESS/DIAGNOSTIC_GUIDE.md`).
- [ ] Artefacts recorded; memory-only answers scored 0.
- [ ] Dimension averages written.
- [ ] Veto caps applied (C1, C2, A5, E1, E2, F6).
- [ ] Maturity band written in one sentence.
- [ ] **GATE:** Band and veto page circulated to AP Manager and Controls (even if that is you).

---

## 2. Holds

- [ ] Last payment run reconstructed: who built, who reviewed, who authorised, who transmitted.
- [ ] Policy and system agree that release is human.
- [ ] Last five vendor bank changes show dual control and before/after.
- [ ] New vendor approval is human.
- [ ] DOA and tolerance edits are human.
- [ ] Close attestation is human.
- [ ] High-value flag clearance has a named role (even if the register is new).
- [ ] **GATE:** C1 is not 0, **or** we have written “L0 only, no Agent 12” on the Wave 1 page.

---

## 3. Classify real work

- [ ] Ten recent exceptions exported.
- [ ] Each line: class A–J, modifiers, who decided, agent ceiling at L1, vendor-demo temptation.
- [ ] Last payment proposal classified the same way.
- [ ] At least one line shows a class A decision a demo would have auto-released — or we record that the demo risk is theoretical.
- [ ] **GATE:** The classification sheet exists. Northline’s April 2026 70-minute exercise is *not* a substitute (fictional).

---

## 4. Map one path

- [ ] Path header filled (`STARTER_GUIDE.md` §6).
- [ ] Stages 1–9 have evidence columns.
- [ ] Five live invoices walked.
- [ ] Out-of-scope types listed (T&E, intercompany, etc.).
- [ ] **GATE:** Matching will only be chartered on a mapped path.

---

## 5. Charter Wave 1

For each of 01, 02, 03, 04, 10, 16:

- [ ] JD/charter complete (purpose, inputs, outputs, duties, exclusions, codes, detection, rollback).
- [ ] Owner named and confirmed they know.
- [ ] Backup named.
- [ ] Object types narrow enough to sample.
- [ ] Autonomy L0 or L1 circled.
- [ ] Language rules included.
- [ ] Signed by owner, controls, process owner.

- [ ] **GATE:** All six signed, **or** unsigned agents are explicitly not running.

---

## 6. Register and informal helpers

- [ ] Autonomy register opened (agent, owner, objects, level, evidence URI, next review).
- [ ] Informal copilots, RPA jobs, and vendor AI features listed.
- [ ] Any helper that can post, send externally, or touch a proposal is off or chartered.
- [ ] **GATE:** No unlisted helper on the pilot path.

---

## 7. Codes, packets, access

- [ ] Starter exception list adopted; local adds go through change control.
- [ ] Evidence-pack minimum written into Orchestrator.
- [ ] Service account / least privilege — no shared UI login for a model.
- [ ] Prompt wrapper stored with the charter (`STARTER_GUIDE.md` §8).
- [ ] Prompt changes require a ticket.

---

## 8. Shadow (L0) — two weeks

- [ ] Operators briefed: work as today; do not rely on shadow output.
- [ ] Coverage report defined.
- [ ] Daily extract/match sample sized.
- [ ] Language sample scheduled (twice in two weeks).
- [ ] Cost ledger opened (licence, model, minutes).
- [ ] Rollback tested on paper.
- [ ] Week-1 review: silent scope? missing owners? EX-OTH explosion?
- [ ] Week-2 review: disagreements coded?
- [ ] **GATE to L1:** Ten operating days; sample written; no out-of-charter objects; language clean; owners in post.
- [ ] If GATE fails: remain L0. Fix. Restart the clock. Do not “try L1 anyway.”

---

## 9. L1 recommend (optional)

- [ ] Recommendations visible to operators.
- [ ] Accept / edit / reject is mandatory and logged.
- [ ] Rejects are reviewed weekly (not punished).
- [ ] Agent 10 still L0 unless Controls opens a separate case (Starter default stays L0).
- [ ] Agent 12 still closed unless C1 ≥ 3 and Wave 2 is open.

---

## 10. Governance rhythm

- [ ] Weekly 30-minute exception mix booked (six weeks minimum).
- [ ] Day-30 Audit observer session booked.
- [ ] Day-90 recertify/demote slot booked.
- [ ] Language incidents have a place in the weekly.
- [ ] **STOP:** payment released on an agent act; bank changed without dual control; “fraud” on a ticket; vacant owner; vendor asks to skip gates.

---

## 11. Scorecard

- [ ] Starter KPI table populated with *sources*, even if some are “not yet.”
- [ ] No savings tile.
- [ ] No fraud-catch tile.
- [ ] No compliance score.

---

## 12. Wave 2 (do not start early)

- [ ] Wave 1 L0 GATE passed.
- [ ] Coded mix exists.
- [ ] 05 / 07 / 08 charters only if fit tests pass.
- [ ] 12 charter only if C1 used (not merely documented).
- [ ] **GATE:** Process owner written approval to open Wave 2.

---

## 13. Decision on next licence

- [ ] We will stay on Starter and remain at L0/L1 on six agents; **or**
- [ ] We will licence Professional for the sixteen specs and gate tables; **or**
- [ ] We will licence Team because more than one function must share; **or**
- [ ] We will apply for Custom Blueprint; **or**
- [ ] We will stop and keep the register of informal helpers only.

Write the choice. Drift is how unofficial L3 happens.
