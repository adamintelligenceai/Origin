## Section: What you receive

Eight packs. One operating system.

### 1. Process mapping

A method for drawing the path an invoice actually takes. Policy maps are filed. Live maps are used. You identify where an agent would sit, what it would touch, and which exceptions it must not swallow.

### 2. Agent library

Named agent designs. Each has a purpose, inputs, outputs, a fence, escalation rules, and stop conditions. The library is a starting architecture, not a catalogue of bots to switch on.

Examples of jobs the library is willing to describe: classify, code, match-and-flag, chase evidence, draft a vendor query, prepare a review pack.  
Examples of jobs it will not romanticise: pay, override a control, “detect all fraud”, close the books.

### 3. Controls

Control objectives written for agent work. Each control has an owner, an evidence artefact, and a failure signal. These sit on the agent, not on the vendor’s security page.

### 4. Governance

Decision rights. Change control. A review cadence. A way to pause an agent that is still “accurate” but no longer inside its fence.

### 5. KPI and measurement

Operating measures: cycle time by class, exception age, human review rate, evidence completeness, fence-breach count, pause events.  
No ROI model that invents a saving. No dashboard that implies the toolkit paid for itself.

### 6. Testing

A pre-production test plan, a historical-sample method, and a go-live evidence list. If you cannot say what would fail the test, you are not ready to run the agent.

### 7. Business case

A narrative structure for executives: problem, scope, operating measures, risks, stop conditions, ask. It is allowed to recommend *not* proceeding. It is not a savings calculator.

### 8. Templates

Agent brief, RACI, exception taxonomy, evidence index, 30-day operating log, decision log, change request.
