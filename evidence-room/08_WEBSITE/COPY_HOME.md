## Section: The problem, stated plainly

Most AP teams are being asked to “add AI” to a stack that already includes an ERP, an AP automation suite, a bank portal, and a shared-services team.

The software is not the gap. The operating system is.

Without a designed agent layer, pilots stay in a slide. Exceptions still sit with the same six people. Nobody can say what the agent is allowed to do, what it must escalate, or which operating measure would count as progress.

That is not a model problem. It is a responsibility problem.

## Section: What Evidence Room is

Evidence Room publishes **AP Agent OS** — a practical operating system you apply across the tools you already have.

It helps you:

- Decide which AP work is fit for an agent, and which is not.
- Write the agent’s job, scope, and escalation path before anyone connects a model.
- Put controls and evidence requirements on the work, not on the vendor brochure.
- Measure operating performance (cycle, exceptions, review load, evidence completeness) without inventing a savings story.
- Brief executives and auditors in language they can defend.

It does **not** replace Coupa, SAP, Oracle, NetSuite, Tipalti, Medius, or the bank. It does not pay suppliers. It does not file your accounts.

## Section: A worked example (fictional)

**Example only. Northline Industrial Group is fictional. Not a client. Not a case study.**

Northline runs a mid-market industrial group. Invoices arrive through an AP automation tool. Exceptions still concentrate on a small AP team. A vendor has offered an “AI agent” for coding and matching.

Before anyone turns the agent on, Northline would use AP Agent OS to:

- Map the live process, not the policy process.
- Fence the first agent to a single invoice class.
- Name the human owner, the control owner, and the evidence pack.
- Choose operating measures that can be observed in 30 days.
- Write the stop conditions before go-live.

That is the work. The model comes later.
