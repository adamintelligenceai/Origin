## Section: The responsibility model (short)

An AP agent is not “live” because a vendor demo ran.

It is live when five things have owners:

1. **Purpose** — the job, in one sentence, that a controller would sign.
2. **Fence** — invoice class, amount, vendor set, and systems in scope.
3. **Escalation** — what the agent must not decide.
4. **Evidence** — what is kept, where, and for whom.
5. **Measure** — which operating numbers will be read, and when the agent is paused.

That is the standard. The toolkit exists to make the standard usable.

## Section: Northline, as a product walkthrough (fictional)

**Northline Industrial Group is fictional. This is an illustration, not a result.**

Northline’s AP lead would not start by selecting a model.

She would:

1. Run the Diagnostic and find the organisation at Level 1 — tools exist, ownership does not.
2. Map the live exception path for PO invoices under a stated amount.
3. Choose one agent from the library: *Match-and-flag*, not *Pay*.
4. Attach controls and an evidence pack.
5. Define three operating measures: exception age, human review rate, evidence completeness.
6. Test on a historical sample before any production traffic.
7. Brief the controller and audit with the Team executive pack.

No payment is autonomous. No saving is claimed. The agent has a job, a fence, and a stop condition.
