# Ninety-day plan

**Product:** Evidence Room — AP Agent OS · Professional  
**Use:** Plan the first 90 days of a Wave 1 layer.  
**Success:** Operating discipline, not a financial close.

Calendar below assumes a Phase 0 already done (diagnostic, holds, owners). If not, days 1–10 *are* Phase 0 and the shadow starts later. Do not compress holds to keep the banner date.

Northline dates are fictional illustrations.

---

## Outcome list (day 90)

All must be true, or the write-up says which failed.

1. Every in-scope inbound invoice has a work object within the Intake SLA you wrote.
2. Validation fail reasons are coded; EX-OTH is measured.
3. Match worksheets exist for the defined sample.
4. Every Agent 10 flag has a recorded human outcome or is still inside its defer clock.
5. Orchestrator shows aging by named owner.
6. No payment released without the human path your policy requires.
7. Autonomy register: every live helper at L0 or L1; no silent promotions.
8. Cost per 1,000 invoices for the layer is recorded (even if small).
9. Day-30 observer session happened.
10. At least one declined promotion or a tabletop demotion is on file.

If first-time match or cycle time moved, record it as **observed**, not as plan achievement.

---

## Days 1–15 — Instrument and L0

| Day | Work |
|---|---|
| 1–2 | Freeze path, codes, sample sizes |
| 3–5 | Sign six charters; open register; kill or list informal helpers |
| 6–7 | Service accounts; packet URIs; cost ledger |
| 8 | Operator huddle: “ignore shadow for posting” |
| 9–15 | L0 running; daily coverage; first language sample |

**Checkpoint A (day 15):** coverage exists; leaks listed. If leaks, do not start the L1 conversation.

---

## Days 16–30 — Shadow complete; observe packets

| Day | Work |
|---|---|
| 16–22 | Dual-review sample; disagreement codes |
| 23–25 | Fix out-of-scope processing; restart clocks on leaked classes |
| 26–28 | Prepare day-30 pack (5+5+5+flags+payment run) |
| 29–30 | Audit (or control reviewer) observes |

**Checkpoint B (day 30):** observer notes reconstructability. Steering monthly #1.

Northline (fictional): observer finds match worksheets missing for 2 of 5 — Wave 1 stays L0 an extra week.

---

## Days 31–60 — Optional L1 on ready classes

| Day | Work |
|---|---|
| 31–35 | L0→L1 case only where gates can be argued (`AUTONOMY_PROGRESSION.md`) |
| 36–50 | L1 accept/edit/reject logged; weekly exception mix |
| 51–60 | Agent 10 remains L0; do not open Agent 12 unless C1 is used and steering agrees Wave 2 start — default is **no** |

**Checkpoint C (day 60):** reject log exists; language clean; owners still in post.

---

## Days 61–90 — Stabilise and recertify

| Day | Work |
|---|---|
| 61–75 | Narrow object types that fail samples; do not widen |
| 76–85 | Draft recertification papers; update cost ledger |
| 86–90 | Steer 90: stay / demote / (rarely) promote prepare on a *packet* class — not payment |

**Checkpoint D (day 90):** outcome list scored true/false. Wave 2 decision is a separate paper.

---

## What is not in the 90 days

- Wave 3–4 agents as live L1 portfolios
- A savings gate
- A fraud KPI
- Multi-ERP rollout
- Touchless posting
- Custom software build

Those belong to later phases or to a different product.

## RACI for the 90 days

| Activity | R | A | C | I |
|---|---|---|---|---|

| L0 operation | Agent owners | Process Owner | IT | Steering |
| Flag outcomes | Controls | Controls | Match | Process Owner |
| Payment runs | Payments | Treasury / policy A | Agent 12 if any | Controller |
| Day-30 observe | Audit (observe) | Process Owner | Transformation | Chair |
| Recertify | Transformation prepares | Chair + Process Owner | Controls, Treasury | Audit |

## Risks (plan-level)

| Risk | Response |
|---|---|
| Close week eats sampling | Pause clock; do not skip samples |
| Owner on leave | Backup named or agent pauses |
| Vendor demo mid-pilot | File under refusals; do not change charter live |
| Sponsor asks for ROI at day 45 | Point to Conservative 0% case; do not invent I13 |
| Informal copilot returns | Incident; register; off |
