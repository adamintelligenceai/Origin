# Frameworks — 10 Named Tools

**Lockup:** EVIDENCE ROOM — AP AGENT OS  

Each framework is a complete one-page tool: name, sentence, when to use, steps, output, refusal. These names should appear consistently in the toolkit, site, and workshops.

---

## 1. Proof-Before-Permission Gate

**Sentence:** The next unit of responsibility is unavailable until the named packet exists.

**Use:** Before any promotion; before a vendor demo becomes a pilot.

**Steps:**  
1. Name the act the agent wants (recommend / prepare / bounded execute).  
2. Write the packet contents for that act.  
3. Inspect a sample.  
4. If any required object is missing, the act is ineligible — not late.  
5. Record the gate on the autonomy register.

**Output:** A dated pass/fail on the register.  
**Refusal:** Confidence scores and fluent tone are not packet contents. Payment release cannot pass this gate because it is not an agent act.

---

## 2. Named-Agent Charter

**Sentence:** If it is not in the charter, the agent does not do it.

**Use:** Monday of Wave 1; any new object type.

**Steps:**  
1. Pick one ID from the sixteen — do not invent a seventeenth until the first six exist.  
2. Fill: job, object types, default level (L0 or L1), human owner, evidence list, exclusions, cost token.  
3. Walk exclusions out loud with Controls.  
4. Sign (owner + process owner).  
5. File next to the register.

**Output:** One charter.  
**Refusal:** “AP AI” is not a charter name. Do not charter Payment Release.

---

## 3. Human-vs-Agent Rights Table

**Sentence:** Agents may be R for preparation. Humans remain A for outcomes that move cash, master data, policy, or attestation.

**Use:** On ten recent exceptions and one payment run, as the library instructs.

**Steps:**  
1. List the acts that occurred.  
2. Mark who *did* the work and who *owned* it.  
3. Circle any act where a model was treated as A.  
4. Rewrite those acts before the next run.  
5. Keep payment, bank details, DOA, close attestation, and self-promotion in the human column.

**Output:** A marked table and a list of illegal As.  
**Refusal:** Do not add a column called “AI-owned.”

---

## 4. Five-Level Autonomy Ladder

**Sentence:** Observation is the default; payment is not a rung.

**Use:** Commissioning, recertification, vendor reviews.

**Steps:**  
1. Place each live agent on L0–L4 with evidence.  
2. Anything undocumented sits at “implied” — treat as a defect, not as L1.  
3. Promote one level at a time after gates.  
4. Demote when residual, cost, or misuse changes.  
5. Leave payment off the ladder.

**Output:** Register rows.  
**Refusal:** No commissioning at L3/L4. No L4-means-pay.

---

## 5. Work-Object Ledger

**Sentence:** If it has no object, it cannot be governed.

**Use:** Orchestrator design; SLA arguments.

**Steps:**  
1. Define objects: invoice, exception, statement line, proposal line.  
2. Require ID, source, current agent, human owner, status, autonomy context, evidence URI, clock, escalation, cost token.  
3. Make Orchestrator the system of record for those fields.  
4. Leave accounting facts in the ERP.  
5. Age by named owner.

**Output:** An object schema and an aging view.  
**Refusal:** Chat threads are not objects.

---

## 6. Exception Atlas

**Sentence:** If it is free text, it is not a mix.

**Use:** Triage design; Root Cause input.

**Steps:**  
1. Start with a short code list (capture, validation, price, quantity, missing GR, defective PO, approval path, supplier wait, internal wait, duplicate hypothesis).  
2. Require a code on every new exception.  
3. Review “other” weekly until it shrinks.  
4. Hand the mix to Root Cause as clusters, not as novels.  
5. Do not encode “fraud” as a code — use duplicate/anomaly hypothesis.

**Output:** A coded mix.  
**Refusal:** Do not sell the atlas as a detection product.

---

## 7. Dual-Human Payment Swimlane

**Sentence:** Annotation in; release out; the agent stops in between.

**Use:** Treasury, AP payments lead, Audit observer sessions.

**Steps:**  
1. Draw proposal → annotation (L1) → human A → human B → transmission → bank.  
2. Remove any chevron that lets the agent column touch release.  
3. Separate vendor-master bank changes into another swimlane.  
4. Sample one run per month.  
5. File the drawing where Thursday can see it.

**Output:** A swimlane and a sample log.  
**Refusal:** No “low-value auto-release” branch.

---

## 8. Wave Plan (90 Days)

**Sentence:** Six agents at observe/recommend is a complete quarter.

**Use:** Transformation planning; Professional START HERE steps 1–12.

**Steps:**  
1. Appoint Process Owner and Controls Lead.  
2. Charter Wave 1 only (01, 02, 03, 04, 10, 16) at L0.  
3. Two weeks of shadow reports.  
4. Promote to L1 individually on gates.  
5. Day 30: Audit observes ten packets and one run.  
6. Waves 2–3 only after the register is real.  
7. Wave 4 optional and never payment.

**Output:** A dated plan.  
**Refusal:** Do not start sixteen L3 agents in week one.

---

## 9. Layer KPI Card

**Sentence:** Measure whether the layer exists before you measure whether it “returns.”

**Use:** Monthly operations; steering packs.

**Steps:**  
1. Fill eight cells: work-object completeness, coded fails, sample packet pass, flag outcomes recorded, aging by owner, payment control held, register integrity, cost/1,000.  
2. Leave first-time match and cycle time in an “observed, table-held-constant” footnote if you must show them.  
3. Do not title the card ROI.  
4. Review cost outliers as demotion candidates.

**Output:** One card, one month.  
**Refusal:** No promised lifts. No Northline figures as targets.

---

## 10. Recertify-or-Retire

**Sentence:** Permission expires unless evidence is produced again.

**Use:** Quarterly; after any material model or prompt change.

**Steps:**  
1. For each live agent, reopen the last gate sample.  
2. Recheck exclusions (especially payment and bank details).  
3. Recheck cost token.  
4. Recertify the same level, demote, or retire.  
5. Record the decision. Silence is not recertification.

**Output:** A quarterly register update.  
**Refusal:** “It’s been running fine” is not a sample.

---

## Naming discipline

Do not rename these in marketing to sound more “AI-native.” The dull names are the product. If a partner deck says “Fraud Shield Framework,” it is off-brand and off-method.
