Complete, named frameworks. Use as LinkedIn posts, Method annexes, or slides inside Professional/Team.  
Each is usable without buying the zip. The zip makes them operational.

## Framework 01 — The Responsibility Model

**Name:** Five Objects  
**Question it answers:** Is this agent actually in production, or only running?

An AP agent is in production when these five have *named owners*:

| Object | Test |
|---|---|
| Purpose | A controller will read the sentence aloud. |
| Fence | Class, amount, vendors, entities, systems are written. |
| Escalation | Out-of-fence states have a human name. |
| Evidence | A third person can find last Thursday’s pack. |
| Measure | Three operating numbers have sources; pause is one sentence. |

If any cell fails, the status is **pilot**, regardless of the vendor’s go-live email.

**Northline (fictional):** purpose = match-and-flag under a signed amount; fence = two plants, PO class; escalation = new vendor and payment; evidence = AP archive; measure = exception age, review rate, fence-breaches.

## Framework 02 — Four Failure Modes of AP AI

**Name:** The Four Failures  
**Question:** Why did the pilot stall or quietly rot?

1. **Tool-led** — software arrived before a job.  
2. **Unfenced** — “all invoices” was the scope.  
3. **Unevidenced** — nobody can reconstruct a decision.  
4. **Unmeasured** — success was a slide, not an extract.

These fail independently. Fixing the model does not fix 3. Buying our toolkit does not fix 1 if you skip START HERE 03.

**Use:** score a current programme 0/1 on each. Four zeros is Level 0. Four ones is still not Level 4 until change control exists (Framework 10).

## Framework 03 — Evidence Ladder

**Name:** Evidence Ladder  
**Question:** What counts as a record?

From weakest to acceptable:

| Rung | Artefact | Status |
|---|---|---|
| 0 | Chat assertion | Not evidence |
| 1 | Screenshot of a demo | Not evidence |
| 2 | Vendor log without brief version | Partial |
| 3 | Inputs + outputs + timestamp | Partial |
| 4 | + brief version + human decision + storage location | Acceptable |
| 5 | + retention rule + named reader | Governed |

Audit is usually asking for rung 4–5. Marketing lives on rung 0–1. Do not confuse them.

## Framework 04 — Agent Design Brief

**Name:** One Brief  
**Question:** What do we write before any model is connected?

Headings, in order:

1. Purpose sentence  
2. In / out of fence  
3. Inputs the agent may see  
4. Outputs it may produce  
5. Escalation list + named receiver  
6. Controls (min. three) + control owner  
7. Evidence pack contents + location  
8. Three measures + sources  
9. Stop conditions + pause owner  
10. Explicit non-goals (pay, override, fraud-omniscience, compliance stamp, close)  
11. Version, date, steward  

If a heading is “TBD”, the brief is not done. TBD is how Level 1 dresses up as Level 2.

## Framework 05 — Control Stack

**Name:** Controls on the work  
**Question:** What sits on the agent, not on the vendor’s security page?

Four layers, bottom-up:

1. **Fence integrity** — how we know it stayed in the box.  
2. **Human release** — a recorded accept / refuse.  
3. **Segregation** — steward ≠ control owner where possible.  
4. **Change** — brief version moves when instructions move.

Each layer: objective, owner, artefact, failure signal.

A SOC report from a vendor can inform IT. It does not replace layer 1–4 on the AP job.

## Framework 06 — KPI Tree (operating, not financial invention)

**Name:** Allowed Measures  
**Question:** What may we read without lying?

```
Operating performance
├── Time — cycle by class; exception age
├── Load — human review rate; queue concentration
├── Integrity — evidence completeness; fence-breaches
└── Control of the control — pause events; change-log completeness
```

**Off the tree (as Evidence Room claims):** savings, ROI, fraud caught, compliance achieved, payment accuracy.

Your finance team may later compute cash effects from *your* extracts. That work is theirs. Do not put it on our page.

Industry averages (Ardent Partners cost / exception / touchless figures; Forrester category writing) sit *beside* the tree as context, cited, never as the trunk.

## Framework 07 — Exception Taxonomy

**Name:** Five Buckets  
**Question:** What kind of exception is this — before we assign it to an agent?

1. **Data** — missing, unreadable, wrong header  
2. **Match** — PO, receipt, price, quantity  
3. **Policy** — threshold, approver, entity  
4. **Vendor** — master, bank, duplicate identity  
5. **System** — tool outage, mapping, duplicate load  

Agents in our library may *flag or pack* 1–2 inside a fence. They do not adjudicate 4 as if they were a fraud product. They do not silently eat 3.

If 70% of a queue is bucket 5, you have a systems problem. Do not buy an agent to launder it.

## Framework 08 — Human-in-the-loop Map

**Name:** Loop Map  
**Question:** Where must a human still act?

Draw four points on the path:

| Point | Human act | If missing |
|---|---|---|
| Entry to fence | Steward confirms the box | Agent sees the world |
| Escalation | Named reviewer | Queue without owner |
| Release | Recorded decision | De facto autonomy |
| Pause | One-sentence stop | Governance theatre |

“HITL” in a vendor brochure is not a map. If you cannot circle these four on your live path, you do not have a loop. You have a slogan.

## Framework 10 — Readiness Levels 0–4

**Name:** The Ladder  
**Question:** Where are we, without flattery?

| Level | Name | Must be true |
|---|---|---|
| 0 | Unscoped | AI is discussed; no written agent job |
| 1 | Tool-led | A tool/model is in trial; fence/owners missing |
| 2 | Designed | Framework 04 exists for one class |
| 3 | Governed | Framework 05 + Evidence Ladder ≥ 4 |
| 4 | Operating | Measures read on a cadence; change control; scale is a written choice |

You do not average levels across plants. You report the weakest live path that still has traffic.

The Diagnostic scores this ladder. AP Agent OS is how you climb it. Neither certifies compliance. Neither promises a saving.
